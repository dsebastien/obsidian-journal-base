# 2026-07-13

## Fixed: frontmatter reappears in Periodic Review card after marking a period done

### Problem

In the Periodic Review view, note cards run in forced `source` mode with
`collapseFrontmatter` enabled, so the YAML frontmatter is folded (hidden) on
open via `EmbeddableEditor.foldFrontmatter()`. Marking a period **completed**
made the raw frontmatter reappear.

### Root cause

Toggling done writes the done property *inside* the note's frontmatter block
(`plugin.setDone` → `markPeriodWithCascade`). The file change propagates through
`PeriodicReviewView.incrementalUpdate()` → `NoteCard.refreshContent()`. In
source mode that calls `EmbeddableEditor.setValuePreservingState()`, which
dispatches a minimal CodeMirror edit landing *inside the folded frontmatter
range*. CodeMirror drops any fold an edit touches, so the frontmatter unfolded
and the fold was never re-applied.

### Fix

`NoteCard.refreshContent()` now re-applies `foldFrontmatter()` after a
state-preserving update when `collapseFrontmatter` is set and the card is in
`source` mode — restoring the same hidden state the card has on open.
(`src/app/components/note-card.ts`)

### Verification

- `bun run tsc`, `bun run lint`, `bun test` (278 pass), `bun run build` all green.
- **Manual UI check still required** (no live vault available to agents): open a
  periodic note in the Periodic Review view with `collapseFrontmatter` on,
  confirm frontmatter is folded, click the done toggle, and confirm the
  frontmatter stays folded (does not reappear). Repeat for un-marking done and
  across period types (day/week/month/…).

### Notes

The re-fold only fires on external content refreshes while the editor is not
focused (focused editors skip refresh unless forced), so it does not fight a
user who has manually expanded the frontmatter to edit it.
