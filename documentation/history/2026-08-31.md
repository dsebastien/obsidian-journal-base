# 2026-08-31

## Fix #43 — Templater duplicated the subfolders a nested date format contributes

`NoteCreationService.createPeriodicNote` passed the whole formatted path as
Templater's `filename` argument while also passing the resolved folder as
`folder`. Templater joins the two, so any format containing `/` had its
subfolder chain applied twice:
`DAILY/2026/2026.3/` + `2026/2026.3/2026-08-30` →
`DAILY/2026/2026.3/2026/2026.3/2026-08-30.md`.

Fix: derive the base name from the formatted path and hand Templater only
that — `folderPath` already carries the format's subfolders (it is sliced
from the resolved `filePath`, which is also what `ensureFolderExists` walks).
The non-Templater path was never affected: it uses `filePath` directly.

`filename` renamed to `formattedPath`, since with a nested format the value is
a folder-relative path, not a name — the old name is what made the misuse look
correct.

## Validation

Live-validated in notesSeb (Obsidian running, real Templater), not just mocks:

- Direct probe of `create_new_note_from_template` reproduced the doubling with
  the old argument and produced the correct path with the base name — this is
  the one thing unit tests cannot prove, since they mock Templater.
- End-to-end through `journal-bases:open-current-daily` with the fixed build
  installed and a scratch config (`YYYY/YYYY.Q/YYYY-MM-DD`) created
  `_jb43-scratch/DAILY2/2026/2026.3/2026-08-31.md` — correct.
- Scratch folder trashed, settings restored (data.json byte-identical to the
  pre-test snapshot), vault git clean apart from the installed build.

Three regression specs added (nested format, nested format with no configured
folder, folder creation before templating); mutation-checked by reverting the
fix — the two argument assertions fail, the rest stay green.
