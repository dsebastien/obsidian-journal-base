# 2026-08-31

## Fix #43 — Templater duplicated the subfolders a nested date format contributes

`NoteCreationService.createPeriodicNote` passed the whole formatted path as
Templater's `filename` argument while also passing the resolved folder as
`folder`. Templater joins the two, so any format containing `/` had its
subfolder chain applied twice:
`DAILY/2026/2026.3/` + `2026/2026.3/2026-08-30` →
`DAILY/2026/2026.3/2026/2026.3/2026-08-30.md`.

Fix: derive the base name from the formatted path and hand Templater only
that — `folderPath` already carries the format's subfolders (it is sliced
from the resolved `filePath`, which is also what `ensureFolderExists` walks).
The non-Templater path was never affected: it uses `filePath` directly.

`filename` renamed to `formattedPath`, since with a nested format the value is
a folder-relative path, not a name — the old name is what made the misuse look
correct.

## Fix #44 — Periodic Review lost columns with two period types in one folder

Two independent defects, and the reporter's diagnosis of the second one was
wrong — worth recording, because their proposed patch would have regressed.

### 1. `detectPeriodType` could not tell two period types apart in one folder

The reporter configured daily and weekly with the _same_ folder (`DAILY`),
distinguished only by their formats (`YYYY/YYYY.Q/YYYY-MM-DD` vs
`YYYY/gggg-[W]ww`). `detectPeriodType` looked at the folder alone and sorted by
folder length, so with equal lengths the array order decided and every note in
`DAILY` came back as `daily`. The weekly column was therefore always empty,
`weekExists` stayed false, and the daily column was locked out by defect 2.

Fix: when several _equally specific_ folders match, break the tie by matching
the basename against each candidate's format. Matching round-trips (parse, then
re-format and compare) — plain parsing is too permissive, `2026-W35` parses
under several patterns. A nested folder still wins outright over a parent one,
so #41's precedence is untouched, and a name matching no format falls back to
the previous behaviour.

### 2. A missing parent note wiped the child columns

`updateVirtualSelector` called `virtualSelector.clear()` whenever
`getParentMissingMessage` fired, blanking the column. Nothing needs it: the
selection context carries the year/quarter/month/week values regardless of
whether the parent note exists on disk, so the child list is perfectly
well-defined. Removed the lockout, the message renderer, and its CSS. Child
periods now stay visible and selectable, and a child note can be created before
its parent exists.

### On the reporter's proposed fix

They attributed the missing notes to `extractDateFromNote` ignoring folder
segments, and proposed matching the full relative path against
`folder + '/' + format`. Probed both claims:

- The tail segment parses fine for both of their formats (`2026-W35` under
  `gggg-[W]ww`, `2026-08-31` under `YYYY-MM-DD`), so date extraction was never
  the failure.
- Full-path matching is actively harmful: the folder name is not a format
  string, so its literal characters are read as tokens — `DAILY/...` converts
  to `DAILy/...` and the parse fails outright. Their snippet returns `null` for
  their own paths.

`extractDateFromNote` left alone.
